# 知识点讲解页（Markdown + KaTeX）· 设计与答辩口径

> 范围：每个考点（118 个）都有一篇独立讲解，入口在星球信息面板「知识讲解」按钮。
> 讲解正文为 **Markdown 稿件**，公式用 LaTeX 书写（行内 `$…$`、独立成行 `$$…$$`），
> 由页面内的渲染器转成排版后的公式（KaTeX，完全本地打包，离线可用）。

## 1. 内容与渲染链路

```
public/data/point_notes.md             ← 118 篇讲解（Markdown + LaTeX，<!-- id --> 分节）
  └─ src/data/notesService.js          ← 首次打开时拉取并按 id 解析、缓存
  └─ src/data/markdown.js              ← 轻量 Markdown 渲染 + KaTeX 数学渲染
  └─ src/components/NotesPage.jsx      ← 全屏阅读页（React.lazy 按需加载）
```

- **按需加载**：KaTeX、字体与渲染器只在第一次打开讲解页时进入网络，主包体积不变；
  打开后浏览器缓存，后续切换考点即时渲染。
- **离线可用**：KaTeX 与字体随构建产物一起打包（`dist/assets`），不依赖任何 CDN；
  断网答辩同样能渲染公式。
- **支持语法**：标题、段落、无序/有序列表、引用、代码、粗体/斜体、链接类文本；
  公式语法覆盖分数、根式、上下标、极限、积分、求和、矩阵/行列式、分段等考研数学常用写法。

## 2. 页面结构

- **头部**：返回星图、章节内「上一个 / 下一个」连续阅读（`i / N` 进度）、关闭。
- **标题区**：考点名、所属科目与章节、高频徽标、数一/二/三范围 chips、「开始做题」。
  范围与高频标记直接来自 `knowledge.json`（逐条对照大纲原文），讲解页不另造结论。
- **正文**：Markdown 渲染的讲解（概念 / 核心公式 / 方法要点 / 易错提醒）。
- **右栏**：关联考点（前置 / 后续 / 关联，点击即切换讲解：跨章节连续跳转）、
  相关题目（题干 + 难度 + 「查看解析」展开参考答案与解析，数据来自题库）。
- **移动端**：单列布局，头部与正文均在视口内，公式块横向可滚。

## 3. 数据质量保障

- `scripts/validate-data.mjs` 新增讲解稿件校验：
  - **覆盖率**：118 个考点必须逐一有讲解分节，且不允许出现不存在的考点 id；
  - **公式可解析**：逐条抽取 1130 条公式，用 KaTeX 以 `throwOnError` 严格解析，
    任何语法错误都会使校验失败（构建前即可发现）。
- 讲解内容按同济《高等数学》、线代/概率论通用教材口径编写；
  **数一/二/三范围一律以 `examScope`（大纲原文核对结果）为准**，页脚明示这一点。
- 渲染端 `throwOnError: false`：即使未来稿件误写坏公式，页面也只降级为红色提示，不会白屏；
  校验脚本负责在数据层拦截。

## 4. 后续替换内容 / 接后台 CMS

讲解稿件是**独立数据文件**，替换无需改代码：

1. 直接编辑 `public/data/point_notes.md`（保持 `<!-- id: 考点id --> … <!-- end -->` 分节），
   运行 `node scripts/validate-data.mjs` 即可校验覆盖率与公式。
2. 接后台：把 `src/data/notesService.js` 的 `fetch('/data/point_notes.md')` 换成你们的内容接口，
   响应体仍按同一分节格式（或在该模块内做映射），页面与渲染器零改动。

## 5. 验收与答辩口径

运行时验证（`node scripts/verify.mjs`）新增检查：

- 讲解页打开：正文含 ≥2 个 Markdown 标题、≥3 个 KaTeX 公式节点（含独立公式块）、无公式错误；
- 「下一个考点」连续阅读：标题与进度正确切换，公式重新渲染；
- 关联考点跳转、关闭后回到星图信息面板；
- 移动端：讲解页完整在视口内，公式渲染正常。

**问：公式是图片吗？** 不是。公式是 LaTeX 文本，页面用本地 KaTeX 转成排版，
可选中、可缩放、体积小，离线可用。

**问：讲解内容哪来的，会不会编造？** 讲解为按教材通用口径撰写的稿件，
范围结论与星球面板同源（`examScope`，逐条对照大纲原文）；页面脚注明示口径来源；
后续接入你们整理的内容时，只替换数据文件即可。

## 6. 公式格式审计（确保"全部公式都是 Markdown → 数学公式"）

用应用内真实渲染器对 118 篇讲解做了全量 DOM 审计（临时脚本，已并入自动化检查），结论：

| 检查项 | 结果 |
| --- | --- |
| 覆盖 | 118 / 118 篇讲解，每篇至少 1 条公式 |
| 公式总量 | 1130 条，KaTeX 严格解析 0 错误 |
| 渲染后错误节点 | `.katex-error` = 0（无一条降级） |
| 可见定界符泄漏 | 0（正文不含裸露的 `$`） |
| 裸 LaTeX 泄漏 | 0（正文不含未被 `$…$` 包裹的 `\frac` 等命令） |

自动化防回归（每次 `node scripts/validate-data.mjs` 强制执行）：
- 每个分节 `$` 定界符必须成对；
- 正文（去除公式段后）不允许出现 LaTeX 命令（`\xxx`）；
- 每篇讲解必须包含至少一条公式，防止"讲义退化成纯文字"；
- 全部公式逐条 KaTeX 严格解析。

运行时验证（`node scripts/verify.mjs`）在讲解页检查中新增：克隆正文并剔除 KaTeX 节点后，
可见文本不得包含 `$` 或 `\命令`——UI 层同样兜底。
