# 小智 AI 智能体（RAG 检索增强）· 设计与答辩口径

> 范围：新增的右下角常驻智能体「小智」。它基于本项目知识库做 **RAG 检索增强问答**：
> 回答考研数学问题、说明数一/二/三范围、梳理前置关联、推荐练习题，并在回答下列出
> **可点击的考点引用**（点击自动切换星系并聚焦星球）。
> 小智是**只读智能体**：不写掌握度、不写做题记录、不改题库，回答仅供学习参考。

## 1. 能力与边界

| 能做 | 不能做 |
|---|---|
| 基于本地知识库回答考点含义 / 范围 / 关联 / 练习推荐 | 修改掌握度、做题记录、题库（无任何写入口） |
| 每条回答附「引用」考点，一键跳转原星球人工核对 | 编造知识库之外的大纲结论或题目答案 |
| 后端代理在线时调用 DeepSeek 生成，断网/未配置时离线降级 | 在前端接触 API Key（Key 只在后端进程环境变量） |

## 2. RAG 流水线（检索在前端，生成为可选）

```
用户提问
  └─① 本地检索（src/data/ragEngine.js，纯前端、可离线）
       · 语料：118 考点（名称/描述/章节/数一~三范围/关联）+ 126 题（题干/选项/解析）
       · 分词：中文二元组（「泰勒公式」→ 泰勒/勒公/公式）+ 英文数字整词，停用词过滤
       · 打分：IDF 加权 + 标题命中 ×2.4 + 整句命中标题 +6，题目文档 ×0.55
       · 输出：Top-6 上下文 + Top-3 考点引用（确定性、同一问题结果可复现）
  └─② 上下文打包（src/data/xiaozhiService.js）
       · 只发检索命中的文档，不发账号掌握度等个人数据
  └─③ 生成（server/ai-proxy.mjs → DeepSeek deepseek-chat）
       · System Prompt 约束：只依据 contexts 作答、不足即说「知识库中未收录」、禁止编造
       · 强制 JSON：{answer, citations[]}；citations 只允许检索命中的考点 id（白名单校验）
  └─④ 降级：代理不可用 / 超时 / 结构异常
       · composeOfflineAnswer 按意图用知识库字段拼装答案（章节清单 / 练习推荐 /
         考点讲解 / 进度查询），UI 徽标变为「离线演示模式」，流程不中断
```

**为什么检索放前端？** ① 答辩演示断网也能答，结果确定性可复现；② 检索零延迟、不产生 token 成本；③ 掌握度等个人状态不出浏览器；④ 后续接入自建知识库时只替换索引数据源，前端交互不变。

## 3. 接入你整理好的知识库 / 大模型（两个对接点）

1. **知识库**：替换 `src/data/ragEngine.js` 中 `buildRagIndex(store)` 的文档来源。
   目前从 `knowledge.json / relations.json / question_bank.json` 装配；若改用独立知识库服务，
   把检索结果映射成同形状文档（`kind/id/name/desc/chapterName/subjectName` 等）即可，
   `retrieve`、`buildSuggestedQuestions`、UI 与代理契约均无需改动。
2. **大模型**：`server/ai-proxy.mjs` 顶部三处常量——`UPSTREAM`、模型名、`DEEPSEEK_API_KEY`。
   启动：`DEEPSEEK_API_KEY=sk-xxx node server/ai-proxy.mjs`（默认 :8787，Vite 已把 `/api` 代理到该端口）。
   任何 OpenAI 兼容上游（通义千问等）只需换 baseURL 与 Key。
   `/api/ai/chat` 的请求/响应契约保持不变：`{question, contexts, history}` → `{answer, citations}`。

## 4. 人机协作与数据安全

- **只读**：小智没有任何写入接口；掌握度变化只来自做题提交链路（见 mastery-and-records.md）。
- **可核对**：每条回答的引用只可能来自检索命中的考点（前后端双重白名单），点击引用跳到原星球与信息面板——用户可以对着原始条目人工判断。
- **不编造**：离线答案只用知识库字段拼装；在线 Prompt 明确「资料不足就说未收录」；题库解析与答案字段本身是人工命验的演示题数据。
- **Key 安全**：前端只请求 `/api/ai/*`，Key 存于代理进程环境变量；代理未配置 Key 时对前端返回 503，前端立即离线降级。

## 5. 验收与演示口径

- 全量运行时验证（`node scripts/verify.mjs`）新增检查：
  - 小智悬浮入口常驻且不越出视口；
  - 对话抽屉打开（4 条建议问题、RAG 就绪徽标）；
  - 提问「泰勒公式属于数几范围？」→ 离线降级答案含考点、数一/二/三范围与「引用：泰勒公式」，徽标为「离线演示模式」；
  - 点击引用 → 抽屉关闭并聚焦「泰勒公式」星球；跨星系引用（高数星系问「逆矩阵」）→ 自动切入线性代数星系并聚焦；
  - 移动端：入口在视口内、抽屉完整在视口内、可关闭。
- **问：AI 会不会改数据？** 不会。小智只读；掌握度/记录/题库的写入口只有做题提交与管理员确认入库。
- **问：离线时回答哪来的？** 检索命中的知识库字段按意图拼装，全部可点击引用核对；徽标明确标注「离线演示模式」。
- **问：会不会编造大纲范围？** 范围字段来自逐条核对大纲原文的 `examScope`；在线模型被要求只引用 contexts，引用白名单过滤任何库外 id。

## 6. 公式输出（与知识讲解页同一套 Markdown → 数学公式管线）

- **在线回答**：System Prompt 要求公式一律使用 Markdown 数学语法（行内 `$…$`、独立 `$$…$$`）；
  前端收到含 `$` 的回答时按需加载 `markdownWithStyles.js`（Markdown 渲染 + KaTeX + 样式），
  公式渲染为排版好的数学式；KaTeX 只在首次出现公式回答时进入网络，主包零增重。
  坏公式降级为红色提示，不崩溃。
- **离线降级**：整理稿直接引用知识库原文（未标 Markdown 的资源文本），按纯文本原样展示，
  不臆造公式；徽标标注「离线演示模式」。
- **知识讲解页**：118 篇讲解全部为 Markdown 稿，公式 100% 由 KaTeX 渲染
  （审计与自动化防回归见 `docs/point-notes.md` §6）。
- 其余界面（星球信息面板描述、题库题干/解析）为题库原始纯文本数据，不属于 Markdown 内容，
  保持原样显示，避免与题库数据一致性校验冲突。
